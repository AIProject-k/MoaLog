# MoaLog 동영상 장면 검색 개발 계획

작성일: 2026-09-26  
기준: 현재 작업 트리의 Android 코드. 동영상 관련 변경과 패키지 경로 변경은 아직 커밋되지 않았다. (2026-09-29 상태는 아래 "진행 상태")

## 진행 상태 (2026-09-29 갱신)

아래 "코드 확인 결과"의 문제들을 Galaxy S23(실제 갤러리: 사진 1,835장 · 영상 184개)과 에뮬레이터에서 고치고 검증했다.
**패키지·앱 ID(`com.moalog.personal`)는 의도한 것이므로 §0의 결정 항목은 닫는다.**

| 계획 항목 | 상태 | 근거 |
|---|---|---|
| 1. 영상 길이·종류를 한 경계로 | ✔ | `media_kind`·`duration_ms` 저장, 그리드는 Coil로 썸네일(캐시) — 항목마다 재조회 없음 |

| 5. 영상 AI 태그 잡음 | ✔ **기기 검증** | 프레임 합집합이 영상당 태그 9.14개를 붙여 영상 앨범이 쓸모없었다 → 투표(프레임의 40% 이상, 최대 5개, `VideoTags`). S23 영상 184개 평균 4.21개, 저장된 프레임으로 태그만 다시 만들어 0.5초 |
| ORT 16KB 정렬 | ✔ | 1.20.0의 JNI 라이브러리가 4KB 정렬 → 1.22.0(둘 다 16KB). 패리티 결과는 두 버전이 한 자리까지 같음 |

**이번에 새로 찾아 고친 버그:**
1. "작년 여름 바다"가 항상 0건이었다 — "작년"(2025)과 "여름"(올해 여름)을 따로 풀어 교집합이 비었다.
2. 기기 폴더 앨범이 하나도 안 나왔다 — `HAVING n>=?`의 바인딩 값이 문자열이라 조건이 항상 거짓.
3. 영상의 촬영 시각·위치를 읽지 않아 전부 "파일 시각"이었다(184개 중 171개가 실제 촬영 시각을 얻음).
4. 검색 결과를 확인 없이 120개 통째로 앨범에 넣고 있었다.
5. 업데이트 직후 갤러리가 빈 화면이 되는 마이그레이션 버그(`is_accessible` 기본값 0).
6. 일부 선택 안내 배너가 검색창 위에 겹쳐 글자가 뒤섞였다.

**측정만 하고 남긴 것:** 프레임 추출은 `OPTION_PREVIOUS_SYNC`로 정했다(정확한 프레임 대비 3배 빠르고 재생 시작 프레임과 일치, 임베딩
코사인 평균 0.97). 이 선택이 검색 품질에 미치는 영향은 평가셋이 생겨야 수치로 말할 수 있다. 자세한 실측은 ANDROID.md §10.5와 §17.

## 목표와 전제

**목표:** 사용자가 기기 안의 사진과 영상을 함께 탐색하고, 한국어 문장으로 영상 속 *보이는 장면*을 찾은 뒤 해당 시점에서 재생하고, 확인한 결과를 내 앨범으로 모은다. 모든 분석은 기기에서 수행한다.

- 첫 배포 범위는 **갤러리 + 영상 장면 검색 + 확인 후 앨범 저장**이다. 음성 입력, 대화·음악 검색, 행동 이해, 자동 편집·내보내기는 별도 단계다.
- “말로 찾아줘”는 우선 **자연어 텍스트 입력**을 뜻한다. 마이크로 말하는 입력은 제품 요구가 확정되면 별도로 설계한다.
- 기사 속 500개 클립·NPU 시연의 처리 속도와 이해 수준은 이 앱에서 검증된 수치가 아니다. 현재 CLIP은 정지 프레임의 시각적 유사도를 계산한다.
- 기존 사진, 즐겨찾기, 사용자 앨범, 교정 결과를 보존하는 것이 새 기능보다 우선한다.

## 접근법 선택

1. **현재 프레임 기반 CLIP 경로를 완성한다 — 권장.** 이미 저장·검색·재생 코드가 있어 변경 범위가 작고 오프라인 약속을 지킨다. 단점은 표본 사이의 짧은 장면, 움직임의 의미, 음성 내용은 놓친다는 점이다.
2. 영상 이해 모델을 바로 추가한다. 동작 설명은 좋아질 여지가 있지만 모델 크기, 기기 메모리·발열·NPU 호환성과 평가 비용이 크다. 현재 검색 평가셋도 없어 개선을 입증하기 어렵다.
3. 서버 분석으로 이전한다. 기기 부담은 낮출 수 있으나 MoaLog의 무업로드·무인터넷 원칙과 충돌한다.

따라서 1을 먼저 제품 수준으로 만들고, **실제 실패 유형을 측정한 후에만** 2를 검토한다.

## 구현 순서와 완료 기준

### 0. 배포·데이터 보존 결정과 현재 변경의 기준선

**대상:** `android/app/build.gradle.kts`, `android/app/src/main/AndroidManifest.xml`, `data/Store.kt`, 기존 v0.2.0 설치본, `android/app/src/androidTest/`.

- [ ] 릴리스의 `applicationId`를 기존 값으로 유지할지 확정한다. 기존 사용자 데이터의 제자리 업데이트가 목표라면 기존 ID와 서명 키를 유지하고, Kotlin `namespace`/소스 패키지 변경과 앱 설치 ID를 구분한다. 새 ID를 유지해야 한다면 자동 DB 이전을 약속하지 말고 별도 데이터 이전 방법과 기존 설치본 처리 방침을 먼저 설계한다.
- [ ] v2 DB에 사진·즐겨찾기·내 앨범·사용자 교정을 넣고 v3로 업그레이드해 값이 그대로 남는지 기기 테스트를 만든다. 재설치·앱 데이터 삭제를 마이그레이션 시험에 사용하지 않는다.
- [ ] 현재 미커밋 영상 코드와 패키지 이동을 기준선으로 기록하고, 이후 단계에서 해당 변경을 덮어쓰지 않는다.

**통과 기준:** 기존 설치본 업데이트 경로가 결정되고, v2→v3에서 사용자 데이터가 보존된다. 실패하면 영상 기능 배포를 중단한다.

### 1. 혼합 갤러리의 데이터와 권한 안정화

**대상:** `data/MediaIndex.kt`, `data/Model.kt`, `data/Store.kt`, `ui/Gallery.kt`, `MainActivity.kt`, 신규 MediaStore 기기 테스트.

- [ ] DB 조회 모델에 `mediaKind`와 영상 `durationMs`를 명시한다. 영상 여부를 `id < 0` 또는 URI 문자열 포함 여부로 여러 화면에서 다시 추론하는 코드를 한 경계로 모은다. 기존 양수 사진 ID와 사용자 앨범 연결은 유지한다.
- [ ] 영상 길이는 MediaStore 동기화 때 저장하고 그리드 렌더링에서 항목마다 `duration`을 재조회하지 않는다. 썸네일 로드 실패 시 기본 영상 카드와 재시도 가능한 표시를 제공한다.
- [ ] 사진만, 영상만, 둘 다, Android 14+ 일부 선택 상태에서 목록·앨범·공유·휴지통을 확인한다. 권한이 바뀌거나 일부 항목 접근이 철회되면 접근 불가 항목이 검색·앨범·뷰어에 계속 노출되지 않도록 동기화 정책을 정한다. 접근 철회를 **원본 삭제**와 구별해 사용자 앨범 관계를 안전하게 보존한다.
- [ ] `Store.blurry()`와 관련 분포·추천은 사진만 대상으로 제한한다. 영상의 완전 중복은 크기·해상도로 후보를 좁힌 뒤 파일 해시가 같을 때만 표시하고, 영상에 사진 연사 규칙을 적용하지 않는다.

**통과 기준:** 혼합 목록의 각 항목이 정확한 썸네일·길이·종류로 보이고, 선택 작업과 권한 변경 후 화면이 일치한다. 영상이 “흐린 사진” 후보에 들어가지 않는다.

### 2. 장면 색인의 신뢰성과 비용 제어

**대상:** `core/VideoSampling.kt`, `work/IndexWorker.kt`, `data/Store.kt`, `ui/Analyzing.kt`, 샘플링 단위 테스트와 기기 통합 테스트.

- [ ] 영상 길이별 샘플링 간격을 평가셋에 맞춰 결정한다. 현재 “약 10초마다, 최대 24장”은 **긴 영상에서 10초 간격을 유지하지 않는다**. 빠른 색인과 더 촘촘한 재분석을 분리할지 측정 후 결정한다.
- [ ] 프레임 추출 실패 한 번으로 영상 전체를 영구 실패 처리하지 않는다. 성공한 프레임·시점은 유지하고, 누락 프레임은 원인과 재시도 가능 여부를 기록한다. 영상이 수정되거나 모델이 바뀌면 해당 프레임 임베딩을 다시 만든다.
- [ ] 사진 우선 처리, 영상별 이어하기, 사용자에게 보이는 남은 작업량·일시정지 이유를 유지한다. 배터리·발열·앱 종료·재시작 시 프레임 중복 작업과 무한 재시도를 확인한다.
- [ ] 색인 중 원본이 이동·삭제되거나 권한이 사라졌을 때 해당 항목만 안전하게 건너뛰고, 다른 영상 처리를 계속한다.

**통과 기준:** 정해진 시험 영상에서 시점별 임베딩이 생성·복구되고, 중단 후 같은 시점을 불필요하게 다시 계산하지 않는다. 10분·1시간 영상의 처리 시간, 메모리, 발열, 배터리 사용량을 **실측값**으로 기록한다. 500개 영상 처리는 이 측정 이후 별도 규모 시험으로 판단한다.

### 3. 검색 결과를 실제 “장면”으로 만들기

**대상:** `data/Store.kt`, `ui/AppViewModel.kt`, `ui/SearchScreen.kt`, `ui/Viewer.kt`, 검색 평가 스크립트·고정 영상 샘플.

- [ ] 검색 결과를 `{mediaId, matchedTimeMs, score, matchType}` 형태로 전달한다. 사진은 시점이 없고 영상은 시점이 있다. 점수는 CLIP 유사도이며 확률처럼 표시하지 않는다.
- [ ] 결과 카드에 일치한 프레임의 미리보기와 근사 시점을 표시하고, 누르면 그 시점 근처부터 재생한다. 프레임 추출 시 요청 시각과 실제 표시 프레임 사이 오차를 측정해 “약” 표기를 유지한다.
- [ ] `saveSearchAlbum()`이 영상 ID뿐 아니라 사용자가 확인한 장면 시점도 저장하도록 앨범 항목을 확장한다. 앨범을 닫았다 다시 열어도 해당 장면으로 이동해야 한다. 사진 앨범의 기존 항목에는 변화가 없어야 한다.
- [ ] 30개 이상 영상과 사람 기준 장면 라벨·시점을 가진 평가셋을 만든다. 짧게 등장하는 물체, 긴 영상, 화면 전환, 비슷한 배경, 한국어 복합 문장을 포함한다. P@5, 놓친 장면 비율, 시점 오차를 기록하고 샘플링 전략 변경 전후를 같은 셋으로 비교한다.

**통과 기준:** “바다가 나오는 영상” 검색에서 사용자가 결과의 일치 시점을 확인하고 그 부근에서 재생할 수 있으며, 저장한 앨범에서도 같은 시점이 열린다. 품질 수치는 실측 보고서로 제시하고 기존 사진 검색 회귀가 없음을 확인한다.

### 4. 자연어로 모으기와 재생 UX 마무리

**대상:** `ui/SearchScreen.kt`, `ui/AppViewModel.kt`, `ui/Video.kt`, `ui/Viewer.kt`, 필요 시 `core/QueryParser.kt`.

- [ ] “지난 여행에서 바다 영상 모아줘”를 **검색 조건 제안 → 결과 미리보기 → 사용자 확인 → 내 앨범 저장**으로 연결한다. 기존 `QueryParser`가 처리하지 못하는 명령은 임의로 실행하지 말고 지원 가능한 검색 조건을 보여 준다. 자동 저장은 하지 않는다.
- [ ] 재생 위치 이동, 일시정지, 음소거, 가로 전체 화면, 화면 이탈·복귀 시 재생 상태를 실제 기기에서 확인한다. 현 `VideoView`로 요구를 충족하기 어려울 때에만 Media3 ExoPlayer로 교체한다.
- [ ] 영상 지원에 맞게 권한·검색·정리·공유 화면의 사진 전용 문구를 수정한다.

**통과 기준:** 사용자가 문장 하나로 장면 후보를 보고, 원하는 후보를 선택해 저장하고, 앨범에서 다시 재생한다. 저장 전후 사용자 확인 절차가 분명하다.

## 별도 후속 단계: 하이라이트와 행동 검색

장면 검색 품질이 확인된 뒤 **사용자 선택 구간의 시작·끝·순서를 조정하는 하이라이트 편집**을 설계한다. 단일 구간 자르기부터 검증하고, 이어 붙이기·내보내기는 Media3 Transformer `Composition`을 후보로 평가한다. 새 파일의 저장 위치, 원본 보존, 취소, 저장 공간 부족, 코덱·HDR 호환성을 별도 완료 기준으로 둔다. “점프하는 순간”, “액션이 많은 영상”처럼 시간에 따른 움직임을 요구하는 검색은 프레임 CLIP의 정확도를 측정한 뒤 필요한 영상 모델을 선정한다. 음성 대화·음악 검색은 오디오 분석을 설계할 때까지 지원 문구에 포함하지 않는다.

## 검증 순서

1. `android/gradlew.bat :core:test :app:testDebugUnitTest :app:assembleDebug --offline` — 순수 로직·컴파일 회귀 확인.
2. **전용 에뮬레이터**에서 짧은 MP4와 길고 장면이 다른 영상, 손상 파일, 사진을 넣고 `StoreMediaQueueTest`, `VideoIntegrationTest`, `PhotoVideoOrderTest` 및 새 마이그레이션·권한 테스트 실행. 현재 통합 테스트는 시드 영상이 없으면 실패하거나 건너뛸 수 있으므로 시드 준비를 자동화한다.
3. 사용자가 승인한 **시험 미디어만 있는 기기**에서 실제 재생·회전·백그라운드·발열·장시간 색인을 확인한다. 개인 갤러리의 영상은 검증 입력으로 쓰지 않는다.
4. 평가셋에서 사진 검색과 영상 장면 검색을 따로 채점하고, 각 단계의 결과와 기기·코덱·영상 길이를 기록한다. 빌드 성공을 모델 품질이나 기기 동작의 증거로 취급하지 않는다.
